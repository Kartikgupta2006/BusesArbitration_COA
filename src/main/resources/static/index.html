Arbitration algorithms

Compare the methods available in this simulator.

Simple

FIFO

Requests are served in arrival order. It is easy to understand and prevents later requests from jumping ahead of earlier ones.

Priority based

Priority arbitration

The device with the highest configured priority is selected first. Lower priority devices may wait if high priority requests keep arriving.

Fair rotation

Round Robin

The arbiter checks devices in a rotating order. This gives active requesters a turn and helps share the bus fairly.

About this project

Project overview and learning objectives.

Bus arbitration is the process of selecting one bus master when two or more devices request control of a shared communication bus at the same time. This simulator demonstrates the idea using a queue and three common selection strategies.

  • ✓Visualize how multiple devices compete for one shared bus.
  • ✓Compare FIFO, priority, and round-robin selection behavior.
  • ✓Review requests, current bus owner, and grant history.
  • ✓Connect a browser interface to Java REST API endpoints.

    Frequently asked questions

    Quick notes about this demo.

    Why can only one device use the bus?

    A shared bus has limited capacity. Arbitration prevents multiple devices from controlling it simultaneously.

    What does the Reset button clear?

    It clears the waiting queue, grant history, counters, and current bus owner in the running Java application.

    Does this demo save data after restart?

    The example backend stores its data in memory. Restarting the app clears the simulation state.
